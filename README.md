# 战争与和平 · 人物关系图谱与拆书笔记

「互动拆书」计划第三部：把列夫·托尔斯泰《战争与和平》（**草婴译本**）拆解为
**卷部章 → 事件 → 时间 × 人物关系 × 地点** 的结构化数据，做成零依赖、可离线运行的交互网页。

**在线体验：** <https://wonton1984.github.io/war-and-peace/>

**源码仓库：** <https://github.com/wonton1984/war-and-peace>

## 这个项目解决什么

读《战争与和平》最大的痛点是**人物关系随时间变化**，而任何一张静态关系图都表达不了这件事：

- 安德烈与娜塔莎：初见 → 舞会重逢 → 求婚受阻 → 订婚 → 悔婚决裂 → 和解死别
- 皮埃尔与海伦：谋产联姻 → 决斗分居 → 丧偶 → 再娶娜塔莎
- 尼古拉与宋尼雅：少年定情 → 承诺 → 家道中落 → 她主动放手
- 陶洛霍夫与尼古拉：同袍 → 赌局陷害 → 挑战 → 1812 并肩游击

本站给每条关系一套**时间切片**：拖动底部的年代滑块 1805→1820，
关系边按年份淡入淡出，悬停即见「此刻他们是什么关系」。
这是本站区别于任何「人物关系图网站」的核心功能。

## 功能

- **动态关系图谱（主视图）**：47 条关系边、140 个状态阶段。
  拖动年代滑块（1805–1820）→ 图谱按年代重连；▶ 可自动播放整部书的关系变迁。
  布局用「3 个年代锚点预计算 + 中间年份线性插值」，确定性、无抖动。
- **「此刻的关系」侧栏**：列出当前年份生效的每条关系与它的状态，以及**关系大事记**
  （该年发生的所有关系转折）。
- **家族谱系**：四大家族各自的世代树 + 跨家族联姻（虚线节点），点击开人物卡。
- **战局地图**：1805 申格拉本 / 奥斯特里茨，1807 埃劳 / 弗里德兰，1812 鲍罗金诺 /
  莫斯科大火 / 塔鲁季诺 / 别列津纳。含战役阶段拆分、行军路线、**撤退路线动画**、
  皮埃尔与安德烈的人物行踪。底图是本地 27 国简化 GeoJSON，**无需联网**。
- **全书 361 章章节卡**：按卷、部、人物、类型筛选；关键词搜索支持人物**别名**
  （如「别祖霍夫伯爵」）与关联事件。人物筛选对**详录与简录一律生效**
  （运行时由 `characters[].chapters` 反向索引，不在 `chapters.js` 里重复存储）。
- **事件卡**：133 张关键事件卡，与覆盖章节双向跳转；含人物、关系变动、主题线、
  人物弧光、小说×史实对照。战役阶段只由显式 `battle` 引用关联，不按年份猜测。
- **主题线**：历史由谁推动 / 自由与必然 / 死亡与顿悟 / 婚姻与幸福 / 贵族与人民 /
  虚荣与真实——六条贯穿全书的议论线，各带提出→推进→解答的节点。
- **人物志**：**197 位**——58 位详录（含弧光阶段、关系网络、出场章节索引，索引由语料机器抽取）+ 139 位简录（身份定位 + 出场章节）。顶栏「人物志」按家族/阵营分组浏览。
- **多译本人名对照**：已录入草婴 / 周煜山对照，另留高植、董秋斯、刘辽逸、娄自良待补；称名待核项见下方检查结果。
- **拆书笔记**：输入即自动保存；按笔记独立存储，支持多标签页同步、Markdown 导出及 JSON 备份/恢复。
  写入失败时明确提示，草稿保留在本页并可导出；离开前提示尚未持久化的内容。旧版整表笔记自动迁移。
  无法解析的旧记录原样保留并随备份导出；含这类隔离记录的备份须先人工核对，导入器不会静默丢弃它们。
- **移动端适配**：768px 以下切换为「图谱在上、面板在下」的堆叠布局。
- **分享链接**：`#ch-2-3-14`（章节）/ `#e-austerlitz`（事件）/ `#y1812`（年份）可直达。

## 数据管线

```bash
# 1. 从底本 epub 抽取逐章正文与人名共现（需自备 epub 放入 corpus/）
python3 scripts/corpus_extract.py

# 2. 仅初始化独立候选；不是日常重建命令，也不是人工数据备份
# 两个脚本均拒绝覆盖已存在的目标（默认 data/*.js 已存在时退出非零），无 --force。
python3 scripts/build_characters.py --output /tmp/characters.init.js  # 仅 58 位详录骨架，不含简录及人工修订
python3 scripts/build_chapters.py --output /tmp/chapters.init.js      # 无 notes_*.py 时明确输出待补骨架

# 3. 批量生产章节卡（见 docs/proposal-brief.md），然后合并
node scripts/merge_proposals.js --dry    # 校验
node scripts/merge_proposals.js          # 落盘（增量、幂等）

# 4. 结构门禁；退出 0 不代表文学内容已全部审定
node scripts/lint_data.js       # 引用完整性 + 受控词表 + 版权门禁
node scripts/trust_guard.js     # 两种模式均运行 lint；有语料再核对精确称名与索引
node scripts/smoke_data.js      # 数据装载冒烟（全局符号 + 交叉引用）

# 内容质量检查（有语料时）
python3 scripts/check_gists.py  # 章节卡 gist：结构 + 人名反查
python3 scripts/check_names.py  # 人物称名是否真是草婴译本写法
python3 scripts/ctx.py <人名>   # 语境提示：[出场]/[转述]/[提及]/[待核]，仍需人工判断
python3 scripts/find_missing.py # 扫出尚未收录的具名人物候选

# 新增事件或简录：先 --dry，确认后再去掉 --dry 落盘
python3 scripts/merge_events.py --dry
python3 scripts/merge_minor.py --dry

# 修订已合入内容：只覆盖提案显式字段，不新增；先 --dry 查看差异
python3 scripts/sync_event_summaries.py --dry  # 包括 day / battle，未指定字段保留
python3 scripts/sync_minor.py --dry
# 同步与合并均拒绝非法字段/引用、重复提案、导入失败；通过校验后原子写入。

# 辅助
node scripts/stats.js           # 输出数据规模（README 数字来源）
python3 scripts/fix_proposals.py   # 提案规范化（gist 超长自动截断）
python3 scripts/verify_events.py   # 事件章节引用反查

# 缺陷回归（管线测试只写临时副本）
node scripts/test_notes.js
node scripts/test_frontend.js
python3 scripts/test_pipeline.py
python3 scripts/test_guards.py
```

### 校验实测结果

2026-09-13 修复后实测，语料在位。数据规模来自 `node scripts/stats.js`：
**361 章 / 361 个 gist、133 个事件、197 位人物（58 详录＋139 简录）、47 条关系边**。
原“150 位简录”目标尚差 **11 位**，未以总人物数替代目标，也未为凑数补录未经核实的人物。

| 检查 | 实测结果与边界 |
|---|---|
| `lint_data.js` | 退出 0；无结构错误，仍列出 `flag` 待核清单。 |
| `trust_guard.js` 章级称名 | 1127 组中 1050 组精确称名、77 组歧义待核。 |
| 人物章节索引 | 核对 2222 条；其中 114 条无精确称名，另有 22 位人物存在超过 3 章的称名索引缺口，均待核。 |
| 事件人物称名 | 508 组中 472 组精确称名、36 组歧义/未证实。 |
| 关系边共现 | 核对 47 条，未发现无精确称名同章共现的边；不等于阶段叙述均已核实。 |
| `smoke_data.js` | 退出 0；数据装载及交叉引用检查通过。 |
| `check_gists.py` | 结构问题 0；15 条人名反查线索待人工复核。 |
| `check_names.py` | A/B 类问题 0；C 类仍有 2 条待核。 |

**精确称名可见 ≠ 人物在场 ≠ 身份、归章和叙述准确。** 泛称、同名和转述不再计作自动出场证据。
结构错误退出非零；`check_gists.py` / `check_names.py` 无语料时退出 2。
完整修复记录与验证边界见 [代码审核报告](docs/code-audit-2026-09-13.md#六修复闭环2026-09-13)。

## 数据可信度

- **卷部章骨架**：底本实测（逐部核对）。唯一出入是第二卷·第四部本版 13 章、
  部分公开目录记 12 章，已在 `structure.js` 打 `flag:"verify"`。
- **人物出场索引**：由语料机器抽取 + 人工抽查，存在同名、指代和转述歧义；不声称逐条准确或完全覆盖。
- **故事内时间**：托尔斯泰只标「一八〇五年七月」这类粗粒度，精确到月的排序
  依赖正文明确线索，未明确者留空，不推测。
- **坐标为示意**：历史地名取今地近似经纬度，非精确测绘。
- UI 的 `flag` 提示待核；没有标记不等于已经逐条人工审定。
